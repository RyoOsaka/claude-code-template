# TDD（テスト駆動開発）ルール

## TDD サイクル

機能開発は必ず以下のサイクルで行う:

```
RED → GREEN → REFACTOR → (繰り返し)
```

### 1. RED（失敗するテストを書く）

- テストファイル（`*.test.ts`）を先に作成する
- `describe` で対象を、`it` で振る舞いを記述する
- 実装が存在しない状態でテストを実行する
- `pnpm test` で **FAIL** を確認してから次へ進む

### 2. GREEN（最小限の実装で通す）

- テストを通す最小限のコードを書く
- 「完璧」ではなく「動く」を目指す
- `pnpm test` で **PASS** を確認する

### 3. REFACTOR（品質改善）

- コードの重複を排除する
- 命名・構造を改善する
- `pnpm test` で **PASS を維持**する

## テストケースの進め方

1. 最も単純な正常系から始める
2. 次に主要な異常系を追加する
3. 境界値・エッジケースを追加する
4. 各テストケースごとに RED → GREEN → REFACTOR を回す

## AI エージェント向けチェックポイント

| フェーズ | 確認事項 | 進む条件 |
|---------|---------|---------|
| RED | テストが失敗する | `FAIL` を確認 |
| GREEN | テストが成功する | `PASS` を確認 |
| REFACTOR | テストが成功し続ける | `PASS` を維持 |

## 禁止事項

- NEVER: テストを書く前に実装コードを書く
- NEVER: RED フェーズで失敗を確認せずに進む
- NEVER: REFACTOR でテスト実行をスキップする
- NEVER: 複数の機能を一度に実装する（1 テスト = 1 機能）
